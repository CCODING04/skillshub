# Step 0 决定项：任务开始时就问

## 原则

**检测 ≠ 决定。** 决定「什么算对」属于人的决策：模型无法依据现有资料判断用户更倾向哪个选择时，给出选项、依据与推荐，由用户拍板。

推演：脚本能告诉我们「1080p 是 1.4 GB、720p 是 68.8 MB、音轨同为 128 kbps」，但「要不要为画质多花 1.3 GB」是偏好，仍要问。

## 决定项清单

| # | 决定项 | 典型选项 | 依据来源 | 无依据时 |
|---|---|---|---|---|
| 1 | **什么算对**：主题、标题方向、立场、口径、验收人 | 忠实还原 / 观点重整 / 编译报道；由用户验收 | 无客观依据 | **必须问，不默认** |
| 2 | 内容形态 | 逐字稿 / 结构重整 / 摘要；引语逐字 vs 书面化；争议段落保留与否 | 无客观依据 | **必须问** |
| 3 | 来源范围 | 全文 / 指定片段；缺失片段补注还是省略；是否多信源校对 | 用户意图 | **必须问** |
| 4 | 视频清晰度 | 320/540/720/1080 | 码率、体积、音轨规格（可测） | 给数据 + 推荐，仍由人选 |
| 5 | 代理 | auto / 自定义 / 直连 | 域名连通性实测 | 给连通性表，仍由人选 |
| 6 | STT 后端 | 平台托管 / 本地 Qwen / FunASR / faster-whisper | 本地模型、GPU、许可、评测数据 | 先检测本地模型；没有则给推荐清单让人选 |
| 7 | 额外成本 | 是否允许积分生图、云 API、GB 级模型下载 | 工具说明与体积 | **先说明再问**，不得静默消耗 |
| 8 | 交付形态 | 长度、配图数量与图型、逐字稿、Markdown、base64 自包含、是否发布 | 用户意图 | **必须问** |
| 9 | 排版主题／配色方式 | 六套内置之一；自定义主色 HEX；色系名（绿／蓝／赭／灰）；氛围词（沉稳／清爽／暖调／学术／杂志感） | 用户偏好（无客观依据）；模型给风格清单与派生方案 | **必须问**；派生时先打印 palette 与对比度供确认 |

## 必须问的硬条件

满足任一条就必须停下来问：

1. 源未收录，或源描述含糊。
2. 可行路径 ≥2，需要取舍。
3. 涉及成本：积分、付费 API、GB 级模型／权重下载。
4. 目标、口径或验收标准不明。
5. 风格偏好没有依据（主题、配色、篇幅、图型、是否发布）。

问之前必须完成：只读探测、环境检测（`detect_options.py`）、必要检索、各路径代价估算，并给出选项 + 依据 + 推荐。**信息不足时不许空手提问，也不许替用户拍板。**

## 提问模板

一次问清，别挤牙膏。用选项 + 依据 + 推荐，不用开放题逼用户想：

```
这个源我没做过，先查了一轮（只读探测 + 网络检索，未动正文）：
· 探测：example.com 返回 200，text/html，默认代理可达（probe.json）
· 依据：检索到该站有公开 JSON 接口（附来源与日期；接口是否仍有效未验证）
· 方案 A：接口取正文，成本低；风险是接口改版 → 回退网页提取
· 方案 B：网页正文提取，稳但可能漏作者日期 → 回退请你贴原文
· 推荐：B，置信度 high，理由是不依赖未验证接口

请你定：
1. 走哪条候选路径？
2. 口径：A 忠实逐字稿 / B 结构重整（推荐，理由：…）/ C 观点评论
3. 交付：篇幅、配图数量、是否附逐字稿与 Markdown、是否发布
4. 渠道参数：清晰度（720p 68.8 MB vs 1080p ~1.4 GB，音轨同为 128 kbps）、
   代理（默认通道对 CDN 502，自定义通道实测可用）、STT 后端（本地已装 Qwen3-ASR-1.7B）、是否允许额外积分
5. 排版主题：墨蓝橘笺（默认）/ 摸鱼绿 / 摸鱼票据风 / 橄榄手记 / 留白禅意风 / 石墨极简风；
   或给一个主色 HEX、色系名、氛围词，我先派生 palette 并把对比度打给你确认
6. 验收：什么算「好」，由你在成稿前确认

确认后我才开始采集。
```

## 红线 vs 可协商

**不可协商（硬规范，不需要问）**：不编造事实与身份；地域／主权表述合规；来源与缺失片段显式标注；不把一致度说成准确率；公众号排版与插图工作流的技术约束。

**可协商（必须问）**：主题、立场、口径、篇幅、图型、是否书面化、是否发布、成本与画质取舍、是否采用某个推荐、**排版主题与配色方式**。

## 判定顺序（S0-A 调研 → S0-B 决策 → 执行）

1. **先调研**：`detect_options.py` 拿环境数据；未知源再跑 `probe_source.py` 做只读探测，并用 WebSearch / domain_search 核实当下做法，形成 `feasibility.json`（≥2 条候选路径 + 代价 + 风险 + 回退 + 置信度）。规范见 `references/feasibility.md`。
2. **再问**：把可行性方案与决定项一起交给用户 —— 不空手问、不猜、不先执行。
3. 有明确事实依据的技术选择 → 用户确认后可执行并说明依据（例：ffmpeg 重采样为 16 kHz 单声道）。
4. 涉及偏好／价值／口径 → 输出选项 + 依据 + 推荐，**停下来等用户**。
5. 用户拍板后写入 `content.json` 的 `decisions` 字段（含选定的候选路径 ID），后续阶段不得擅自改写。

调研做得越扎实，用户那一次选择越轻松；但**依据再充分也不构成替他决定的授权**。
