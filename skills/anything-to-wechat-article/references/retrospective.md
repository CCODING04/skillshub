# 范式文章流程复盘（2026-11-12）

范式：`wechat-article.html` —— 由 X 上的一段 21 分 24 秒现场演讲视频，经音频提取、语音转写、多信源校对，整理成公众号文章并配 4 张自制信息图。

## 一句话概括

这条流程真正做的事，不是「把视频变成文章」，而是**把不可控的输入，收敛成一个可控的中间层，再映射到目标平台的硬约束**。中间层（文本 + 结构化章节）越干净，后面的排版和配图越稳。

## 阶段复盘

| 阶段 | 输入 → 动作 → 产出 | 做对的关键 | 踩过的坑 |
|---|---|---|---|
| 探测 | 链接 → 解析媒体清单、测通道 → 清晰度/音轨/字幕元数据 | 先小成本探测再下载；失败时区分「域名被挡」与「全网不通」 | 第一次 502 后没有立刻问用户要通道，自己试了多条路 |
| 采集 | 直链 → 720p MP4（68.8 MB）→ ffmpeg 16 kHz 单声道 mp3 | 发现各清晰度音轨都是 128 kbps，画质对转写无增益；顺手从 HLS 主列表挖到独立音轨与自动字幕 | 未先问画质偏好 |
| 转写 | 音频 → 平台 STT → 带时间戳文本 | 同时保留 wav/mp3，用轻量 mp3 送转写 | 底层模型不暴露，当时未声明是托管黑盒 |
| 校对 | 转写 + 平台字幕 + 官方演讲页 → 六章结构 + 8 条校对备注 | 保留原始识别错误、另列备注，不偷偷改正文；还原被连读的章节编号 | 后来实测发现字幕与平台转写 CER 仅 2.31%，**并非独立信源**，当时称「第二信源」不严谨 |
| 配图 | 章节要点 → 4 张矢量式 HTML 版式 → 2x PNG | 先定每张图回答什么再选图型；不把讲者个人选择画成标准答案；逐张看图修溢出 | fig3 溢出、fig4 压字，返工两轮才定稿 |
| 排版 | 结构化内容 → 全内联样式 HTML + base64 图 + 独立 PNG + Markdown | 微信过滤 style/class，全部内联；图片双轨；用 p 包 img 而非 figure | 913 KB 的 HTML 粘贴后台仍需手动上传图片 |
| 校验 | 成品 → 首屏截图 + 结构计数 | 图片 4、占位符 0、引用块 10、章节 6，逐项核对 | 无自动化校验器，靠人工命令 |

## 做对的八件事（要固化）

1. **先探测后下载**：HEAD + 播放列表拿到时长、码率、音轨、字幕，才决定取哪个清晰度。
2. **失败二分定位**：直连／同域其他子域／协议／域名变体／备用 API 分别测，把「网络问题」缩到「某域名被代理拦」。
3. **多信源校对但标注口径**：专名（Grok）、章节编号、缺失片段都显式说明；引语书面化、小标题自拟写进文末。
4. **产物分层**：`work/` 中间产物、根目录交付物、`images/` 可上传素材；Markdown 由模板派生而非手抄两份。
5. **中间层思维**：先得到干净的章节结构，再谈版式；换渠道不必重做排版。
6. **插图不靠生图**：中文标注交给 DOM，零额外积分、无乱码；内容与结构先行，视觉最后。
7. **校验闭环**：渲染 → 看图 → 修 → 重渲染 → 复看 → 首屏截图。
8. **成本与合规前置**：不静默下载 GB 级权重、不静默消耗积分、地域表述按规范。

## 可改进（skill 里已补）

- Step 0 决策卡点缺失：画质、代理、STT 后端、口径应在动手前一次性问清。
- 独立信源判断要靠数据：同源检测（两两 CER）应先做，再决定能不能互证。
- 需要自动校验器替代人工命令。
- 本地模型与术语表应作为可选后端，专名不应只靠人工校对。
- 评测口径要区分「一致度」与「准确率」，参考不是金标准时不得标称准确率。

## 决策卡点的进化（用户 14:09 提出）

原设计是「Step 0 先问」。用户补出第三个选项：**不猜，也不空手问，而是先做可行性调研** —— 只读探测 + 检索当前网络知识 + 结合已有知识，形成带依据、成本、风险与失败回退的方案，再交人拍板。

这把「不替用户选择」从消极约束变成积极职责：**模型负责把依据做扎实，人负责决定**。对应改动：

- S0 拆为 **S0-A 调研 / S0-B 决策**，Workflow 增加调研阶段；
- 新增 `references/feasibility.md`（feasibility.json 结构、置信度措辞、调研红线）与 `scripts/probe_source.py`（只读探测）；
- `decisions.md` 判定顺序改为「先调研 → 再问 → 后执行」，提问模板改为带方案问；
- anything 自适应明确为「结构层 + 渠道层可自适应，意图层永不自适应」。

红线：调研只读、不下载正文、不登录、不消耗积分；查不到就写「未找到可靠依据」；草稿标 `draft-not-executed`，不把可行性方案说成跑通过；**方案再明显也不跳过拍板**。
